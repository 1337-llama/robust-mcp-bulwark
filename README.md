# MCP Bulwark

> A security gateway for AI agents. MCP Bulwark sits between an agent and its MCP tools. It pins and inspects tool definitions, enforces least-privilege policy on every tool call, redacts secrets, and keeps a tamper-evident audit trail. Every protection is proven by an attack test that runs in CI.

**Status: 🚧 Building. The attack suite (spec 001) and the transparent, audited proxy (spec 002) work; the defenses come next.** This project follows a spec-driven process ([docs/WORKFLOW.md](docs/WORKFLOW.md)): idea → design → specs → build. The [design document](DESIGN.md), [decision records](docs/adr/), [design review](docs/reviews/design-review-1.md), and [specs](specs/README.md) are part of the project. Every spec was checked by an independent reviewer session before merge.

## The problem

AI agents get real capabilities (files, shells, email, cloud APIs) through the **Model Context Protocol (MCP)**. That opens new attack paths:

```
 Agent ──► [ poisoned tool description ]   ──► model follows hidden instructions
 Agent ──► [ tool changes after approval ] ──► "rug pull": trusted tool turns malicious
 Agent ──► [ web page with injection ]     ──► agent reads private data ──► sends it out
```

Published research shows popular models often fall for tool poisoning: several exceeded 60% attack success in the MCPTox benchmark (2025). Most current defenses are install-time scanners or chat-content filters, and few publish evidence that their protections work.

## What MCP Bulwark does

| Capability | How |
|---|---|
| **Pin and diff** | Records a fingerprint of every approved tool definition. Any change quarantines the tool and shows a readable diff. |
| **Inspect** | Analyzers flag hidden instructions, invisible Unicode, cross-tool manipulation, and suspicious schemas. |
| **Decide** | Policy-as-code allows or denies each call: which tool, with which arguments (paths, domains, patterns). |
| **Redact** | Detects secrets in tool arguments and results before they leak. |
| **Record** | Hash-chained, SIEM-friendly audit log of every decision and its reasons. |
| **Contain** *(v0.2)* | Once a session has touched both private data and untrusted content, tools that can send data out are locked down. |

It's a drop-in wrapper: `bulwark wrap -- <server command>`.

## Proven by attacks, not claims

The repo includes an **attack suite**: deliberately malicious (harmless) MCP servers plus a scripted client that replays exactly what a hijacked agent would send. On every change, CI runs each attack twice: once directly, where the attack must succeed, and once through Bulwark, where it must be blocked. ## Try it (from source)

Requires Go 1.27 or later.

```bash
go install github.com/1337-llama/robust-mcp-bulwark/cmd/bulwark@latest
```

Then change your MCP client's server command so it runs through Bulwark:

```json
{"command": "bulwark", "args": ["wrap", "--server-id", "fs", "--mode", "warn", "--", "npx", "-y", "@modelcontextprotocol/server-filesystem@<exact-version>", "/workspace"]}
```

`warn` (the default) records everything and blocks no tool calls yet; strict parsing and the size, depth and notification-rate limits apply in every mode. Check the audit log:

```bash
bulwark audit tail --server-id fs
```

```bash
bulwark audit verify --server-id fs
```

So far `bulwark wrap` is a strict, transparent, fully audited proxy. The defenses (pinning, analyzers, policy, secret redaction) arrive with specs 003–007; see the roadmap below.

## Limitations

- **Bulwark is not a sandbox.** A malicious stdio server is local code running as you: it can read files or use the network directly, without going through MCP (AR-1). Run untrusted servers in a container, for example `bulwark wrap -- docker run -i --rm --network none <image>`, and keep Bulwark's state directory out of any directory mounted into it (AR-2).
- **Bulwark adds no request timeout.** A server that never answers can stall its client, with or without Bulwark.
- **Prompt injection is limited, not solved.** Bulwark restricts what a hijacked agent can see and do; it can't make a model ignore instructions.
- **The audit chain detects edits, not truncation.** Modified, inserted, deleted or reordered records are caught; a truncated tail or a wholly rewritten file needs an external anchor (planned for v0.2). Up to one second of records can be lost in a crash.

## Roadmap: attacks first, then defenses

| Milestone | Deliverable |
|---|---|
| **M1** | Attack suite + transparent stdio proxy + audit log |
| M2 | Tool pinning, static analyzers, CLI, detection-rate tests |
| M3 | Policy engine, argument constraints, secret redaction, one-command demo, signed release. **v0.1** |
| M4 | Remote (HTTP) servers, multi-server support, taint tracking, human approval. **v0.2** |
| M5 | ML injection classifier, OpenTelemetry/OCSF export, optional live-model mode. **v0.3** |

Why this approach? See [ADR-0001](docs/adr/0001-lab-first-roadmap.md) and [ADR-0002](docs/adr/0002-gateway-with-attack-suite.md).

## Safety

The attack lab (`lab/`) contains **intentionally malicious MCP servers for testing only**. They use fake canary secrets, record "exfiltrated" data only to a local log file, and make no network calls at all. Once the suite is built, Linux CI will fail if any process opens an internet socket. Don't connect them to agents that have access to real data.
